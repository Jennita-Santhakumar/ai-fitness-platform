- [x] **Day 1: Setup and scaffold**
  - Goal: Working dev environment and repository.
  - Commit: `chore: scaffold repo with health endpoint`
  - Learning Log:
    - Initialized modular FastAPI architecture (`app/api`, `app/core`, `app/models`, `app/schemas`).
    - Configured `.gitignore` to prevent leaking virtual envs (`.venv/`) and secrets (`.env`).
    - Verified `GET /health` endpoint functionality with automated `pytest` test suite.
- [x] **Day 2: Docker Compose + database connection**
  - Goal: API and Postgres run together with one command.
  - Commit: `feat: dockerize api and postgres`
  - Learning Log:
    - Built Dockerfile for containerized Python 3.11 environment and created multi-service docker-compose.yml with PostgreSQL and data volume.
    - Implemented Pydantic-settings config (`app/core/config.py`) and SQLAlchemy engine, sessionmaker, and `get_db` generator (`app/core/db.py`).

- [x] **Day 3: Models and migrations**
  - Goal: Database tables created through Alembic.
  - Commit: `feat(db): add models and initial migration`
  - Learning Log:
    - Designed relational models (`User`, `Workout`, `Exercise`, `WorkoutSession`) using SQLAlchemy 2.0 type annotations and mapped columns.
    - Established foreign key constraints with cascade delete behavior (`workouts.user_id`, `exercises.workout_id`, `sessions.user_id`).
    - Configured Alembic migration environment (`alembic/env.py`) and generated initial migration script (`0001_initial_tables.py`).
    - Verified model relationships and cascade behaviors via automated pytest suite.
- [x] **Day 4: Auth part 1: register**
  - Goal: Users can register with a hashed password.
  - Commit: `feat(auth): add user registration with bcrypt`
  - Learning Log:
    - Implemented Pydantic user schemas (`UserCreate`, `UserRead`) guaranteeing zero password/hash leakage in API responses.
    - Built cryptographically secure password hashing and verification using `bcrypt` salting (`app/core/security.py`).
    - Developed `POST /auth/register` with conflict rejection (`HTTP 409`) on duplicate emails.
    - Wrote 4 comprehensive tests (success, duplicate rejection, invalid email, zero password leakage) passing with 100% success.
- [x] **Day 5: Auth part 2: login and JWT**
  - Goal: Login returns tokens; protected routes check them.
  - Commit: `feat(auth): add login, jwt tokens and current user dependency`
  - Learning Log:
    - Built JWT access token (30-min expiration) and refresh token (7-day expiration) signing & decoding using `python-jose` (`app/core/security.py`).
    - Implemented `POST /auth/login` accepting OAuth2 password form and returning dual tokens.
    - Added `POST /auth/refresh` enabling secure token renewal without re-prompting user credentials.
    - Implemented `get_current_user` dependency validating signature, expiration, and user state, protecting `GET /users/me`.
    - Added automated tests for successful login, invalid credentials, missing token, expired token, and refresh exchange (13 tests passing).
- [x] **Day 6: CRUD for workouts, exercises, sessions**
  - Goal: Authenticated users manage their own data.
  - Commit: `feat(api): add workout, exercise and session crud`
  - Learning Log:
    - Designed Pydantic schemas with validation rules for Workout, Exercise, and WorkoutSession.
    - Implemented full RESTful CRUD routers with pagination (`limit` & `offset`).
    - Enforced strict user ownership isolation across all endpoints—unauthorized access attempts return `HTTP 404 Not Found` to prevent IDOR resource enumeration.
    - Added comprehensive multi-user ownership test suite passing with 100% success (17 tests total).

## Milestone 2: LLM Plan Generation (Days 8–14)

  - Goal: One interface, first provider working.
  - Commit: `feat(llm): add provider interface and groq client`
  - Learning Log:

    - Created throwaway verification script (`scripts/test_groq.py`) and automated unit tests for success, missing credentials, and timeout handling (21 tests passing).
- [x] **Day 9: Gemini and Ollama providers**
  - Goal: Three providers behind one interface.
  - Commit: `feat(llm): add gemini and ollama providers`
  - Learning Log:
    - Implemented `GeminiProvider` using Google Generative Language REST API with structured JSON output and 20s timeout.
    - Implemented `OllamaProvider` connecting to local Ollama daemon for offline zero-cost fallback.
    - Implemented `get_llm_provider` factory in `app/llm/factory.py` with runtime configuration dispatching.
    - Built provider latency benchmark script (`scripts/compare_providers.py`) and added unit test coverage (30 tests passing).
- [x] **Day 10: Plan schema**
  - Goal: A strict Pydantic model for a multi-week plan.
  - Commit: `feat(plans): add plan pydantic schema`
  - Learning Log:
    - Designed strict Pydantic hierarchy (`Plan`, `Week`, `Day`, `ExerciseItem`) for validating multi-week AI workout plans.
    - Added domain validators enforcing 1-12 weeks, 1-7 days per week, and sets/reps strictly > 0.
    - Verified automatic JSON Schema export via `Plan.model_json_schema()` for zero-drift LLM prompt injection.
    - Implemented 5 comprehensive unit tests checking valid plans, week count bounds, day count bounds, and negative values (35 tests passing).
- [x] **Day 11: Prompt templates + generation**
  - Goal: Generate a plan from user inputs.
  - Commit: `feat(plans): add prompt templates and plan generation`
  - Learning Log:
    - Built dynamic system prompt embedding `Plan.model_json_schema()` and strict safety/exercise rules (`app/llm/prompts.py`).
    - Implemented user prompt generator mapping goal, level, equipment, days/week, weeks, and physical limitations.
    - Implemented `strip_code_fences` to sanitize markdown code blocks and conversational filler from LLM outputs.
    - Built `generate_plan(inputs, provider)` and tested 5 distinct persona outputs in `docs/prompt_log.md` (42 tests passing).
- [x] **Day 12: Reliability: retry, timeout, failover**
  - Goal: Bad output and outages do not crash the app.
  - Commit: `feat(llm): add retry, timeout and provider failover`
  - Learning Log:
    - Built self-correcting validation retry loop (up to 2 retries) appending exact Pydantic/JSON errors to the prompt.
    - Implemented multi-provider failover chain across Groq, Gemini, and local Ollama (`app/llm/resilience.py`).
    - Added structured JSON logging tracking provider selection, attempt numbers, and failure causes.
    - Defined custom `PlanGenerationError` and mapped it to `HTTP 502 Bad Gateway` in FastAPI exception handlers (46 tests passing).
- [x] **Day 13: Plan endpoints + storage**
  - Goal: Plans are saved and fetched by the user.
  - Commit: `feat(plans): add plan endpoints and storage`
  - Learning Log:
    - Created `PlanRecord` SQLAlchemy model with JSON columns, foreign key to User, and calendar tracking fields (`is_active`, `start_date`).
    - Added Alembic migration script `0002_add_plans_table.py` and exported model in `app/models/__init__.py`.
    - Implemented protected REST endpoints: `POST /plans/generate`, `GET /plans`, and `GET /plans/{id}` with strict user ownership isolation.
    - Added defensive input bounds (max 12 weeks, max 500 characters on free text fields) and wrote automated tests (49 tests passing).
- [x] **Day 14: Mocked-LLM tests and tag v0.2**
  - Goal: LLM logic is tested without real calls.
  - Commit: `test(plans): add mocked llm tests`
  - Learning Log:

    - Added unit tests for valid JSON, self-correction retry on invalid JSON, persistent failure exhaustion, and timeout failover.
    - Injected `FakeProvider` into FastAPI endpoints using `app.dependency_overrides[get_llm_providers]`.

  - Goal: Long LLM calls no longer block requests.
  - Commit: `feat(jobs): add async plan generation`

- [x] **Day 18: Weekly review**
  - Goal: LLM summarizes your week.
  - Commit: `feat(jobs): add weekly review task`
  - Learning Log:
    - Created `WeeklyReview` model aggregating past 7 days of training metrics (`total_sessions`, `total_minutes`, `total_volume`) with unique period constraint.
    - Added Alembic migration `0004_add_weekly_reviews_table.py` and exported model in `app/models/__init__.py`.
    - Implemented `generate_weekly_reviews` background task and configured Celery Beat schedule for Sundays at 20:00 UTC.
    - Added protected `GET /reviews/latest` endpoint returning the most recent coaching summary and next-week suggestions.
    - Wrote tests verifying metric aggregation from real `WorkoutSession` and `Exercise` data, zero-session handling, idempotency, and isolation (76 passing tests).
- [x] **Day 19: Retries, idempotency, failure handling**
  - Goal: Failed tasks retry safely; duplicate deliveries do not corrupt state.
  - Commit: `feat(jobs): add retries and idempotency`
  - Learning Log:
    - Configured automatic retry with exponential backoff and full jitter (`autoretry_for=(Exception,)`, `retry_backoff=True`, `retry_backoff_max=300`, `retry_jitter=True`, `max_retries=3`) on Celery background jobs to prevent thundering herd problems.
    - Implemented client idempotency key (`idempotency_key`) on `PlanGenerateRequest` and cached check inside `generate_plan_task` to prevent duplicate LLM calls and duplicate plan generation on network retries.
    - Built a dead-letter failure tracking mechanism utilizing Celery's `@task_failure.connect` signal to capture permanently failed tasks, logging structured context and pushing records to `celery:dead_letter_queue` in Redis.
    - Mastered Celery eager test-mode internals (`task_store_eager_result=True`, in-memory cache isolation) achieving 80 passing automated unit/integration tests with 100% green status.

    - Generated Alembic migration `0005_add_strava_tokens_to_user.py` storing athlete ID, tokens, expiry, and scopes.
    - Added automated unit test suite covering complete OAuth lifecycle and token refresh (27 tests passing).

  - Commit: `feat(integrations): add strava activity sync`
